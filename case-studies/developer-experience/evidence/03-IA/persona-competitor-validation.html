Inputs 02 / 08

The eight personas at a glance.

Three Mode personas model the lifecycle axis. Five Extreme personas pressure-test the spectrum of expertise and risk tolerance. Each persona carries their consistent color through the rest of this document.

M

Maya

Mode 1 · Trial & Trust
Senior engineer evaluating in a 30-min window.
Breaks at L1 · no working code on hero
Needs verb-led entry and immediate code visibility.
D

Diego

Mode 2 · Implementation
Mid-level engineer building a real integration.
Breaks at L2 → L4 · empty response until Try-It
Needs response shapes before auth and walkthroughs cross-linked to endpoints.
S

Sara

Mode 3 · Operations
SRE on call returning when production breaks.
Breaks at L5 · does not exist
Needs status, deprecation, rate limits, and logs reachable from anywhere.
A

Aria

Extreme · Curious & Code-shy
PM or junior who reads code but does not write OAuth.
Breaks at L2 · OAuth wall
Needs anonymous mock and placeholder keys in samples.
L

Liam

Extreme · Code-Fluent Speed-runner
Senior engineer wanting the fast path from hero to ship.
Breaks at L5 · production errors with no docs
Needs hero code, sticky language, and visible ops surface.
D+

Diego (Ops-aware)

Extreme · Ops-aware Builder
Refuses to integrate without verifying the ops story.
Breaks at Evaluation · L5 not visible
Needs L5 readable during evaluation, not only after deployment.
M+

Maya (Curious)

Extreme · Time-pressured
Bouncier variant of Mode Maya. Sub-60-second window.
Breaks at L1 · faster bounce
Needs sub-10-second comprehension and frictionless first call.
R

Reza

Extreme · Compliance-First Enterprise
Compliance or security reviewer at an enterprise buyer.
Breaks at Evaluation cannot start
Needs scopes, audit log, deprecation horizons before any code runs.

The seven competitor portals.

Each portal solves the developer onboarding problem in a different shape. We named these shapes "archetypes" in the original layering deep-dive. Each one earns at least one persona slot in the matrix below.

Stripe

Capability-First
Verb-led tiles. Pre-populated responses. Full L5 surface in dashboard.
docs.stripe.com

Twilio

Product-Line × Use-Case
Two-axis L1. Quickstart deep-links to API reference at every step.
twilio.com/docs

ClickUp

Capability Cards
Four-card landing (API · MCP · Webhooks · OAuth). Verb-led, modest L5.
developer.clickup.com

Figma

Choose-Your-Surface
REST / Plugin / Widget split. Personal access tokens, no OAuth dance.
developers.figma.com

Postman

Task-Mode Card Grid
Collections, Mock Servers, Monitors as primary primitives. Mock-first auth.
learning.postman.com

Google Workspace

App-Grid Two-Axis
Apps × API surfaces grid. Explicit deprecation calendar. Quotas dashboard.
developers.google.com/workspace

Claude (Anthropic)

Code-on-Hero
Working curl on hero with placeholder key. Surface picker. Clean L4.
platform.claude.com/docs

Synthesis 06 / 08

Patterns that earned their place in D3.

A pattern earns inclusion in the D3 IA when it shows up in the matrix for more than one persona and is validated by more than one competitor. Eight patterns met both bars. Each is shown with the persona group it serves and the D3 surface where it lives.

01

Working code on hero

A curl block visible above the fold with a placeholder key. The shape of the response is readable before any action.

ServesMaya, Liam, Maya-Curious
FromClaude · Stripe
02

Tiered auth ladder

Anonymous mock first, then sandbox key, then live OAuth. Each tier returns real data. Users earn the next tier by working at the current one.

ServesAria, Diego, Maya
FromPostman · Claude
03

Pre-populated response shapes

Every endpoint page ships with a realistic example response. The contract is readable before Try-It is ever clicked.

ServesDiego, Liam, Aria
FromStripe · Twilio
04

Walkthroughs cross-linked to Reference

Every walkthrough step deep-links to the endpoint reference inline. Every endpoint page shows "Used in walkthrough" link back.

ServesDiego, Liam, Aria
FromTwilio · Figma
05

L5 Operations surface

Status, Deprecations, Rate limits, Webhook events, Logs, Runbook. The portal does not end at Reference.

ServesSara, Diego-Ops, Reza, Liam
FromStripe · Twilio · Postman · Google · Claude
06

Explicit deprecation calendar

Sorted by horizon. Sub-30-day items flagged urgent. Each deprecation linked to migration walkthrough.

ServesReza, Sara, Diego-Ops
FromGoogle · Claude · Stripe
07

Sticky language tabs

Language selection persists across every page in the portal. cURL, Python, Node, Ruby, Go, Java, .NET all first-class.

ServesDiego, Liam
FromStripe · Claude
08

Breadcrumb across all pages

SDK › Group › Page. Click any crumb to fast-travel. Replaces the flat-depth confusion the current rail creates.

Synthesis 07 / 08

The one move no competitor inspired.

Every pattern in section 06 was borrowed. One pattern in the D3 IA is not borrowed. It is the only move Beacon makes without precedent from the seven portals we audited.

✨ THE UNBORROWED MOVE

Copilot as Navigation Spine.

None of the seven competitor portals has shipped a docs-native conversational assistant positioned as a cross-layer navigation primitive. Stripe has a chat assistant in the dashboard, not in the docs. Claude has an "Ask Docs" affordance, but it is a search-and-summarize surface, not a navigation primitive.

✗Stripe
✗Twilio
✗ClickUp
✗Figma
✗Postman
✗Google
✗Claude

Beacon's Copilot is the only place where the IA innovates, not iterates. Anchored to the current SDK, group, and page. Seeded prompts scoped to the surface. Output renders into the surface, not into a chat thread. Deep-links to other groups when the answer references them.

Served in D3 as
A persistent right-side affordance on every page. v1 ships as the anchored drawer. v2 collapses into a vertical spine across Quick Start, Build, Reference, Operate.
