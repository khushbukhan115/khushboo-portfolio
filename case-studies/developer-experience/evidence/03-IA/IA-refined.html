The IA 02 / 09

What is preserved.

Six surfaces that the audit confirmed should not change. v2 is conservative on the foundations developers already rely on.

KEPT

SDK picker (now SDK × Version)

The orthogonal axis remains untouched in spirit. The audit added a version dimension to it. The mechanism stays the same.

KEPT

Quick Start name

Industry-standard term. Bookmarks and Stack Overflow references survive. Confirmed by audit lens 7.

KEPT

Endpoint pages

The portal's strongest surface. v2 promotes them into Reference but does not change page layout.

KEPT

Language tabs

Sticky language selection extends across walkthrough samples, SDK pages, and code blocks portal-wide.

KEPT

Try-It panel mechanics

Same inline call surface. Now formally inline-primary on every endpoint plus standalone playground node.

KEPT

Existing URLs (with additions)

v1 was non-breaking. v2 stays non-breaking for existing URLs. New URLs are additive: /operate, /build, /reference root paths.

Rules 04 / 09

Cross-cutting rules.

Twelve clarifications the audit caught. None of these change the IA structure. They make explicit what was implicit in v1.

Cross-link routes

Next-step CTAs out of Quick Start.

After Quick Start › First call, show two explicit Next CTAs: "Build a real integration → Build › First integration" and "Browse the API → Reference › Endpoints".

A2.1
Cross-link routes

Conditional "Used in walkthrough" behaviour.

Show the link on an endpoint page only if at least one walkthrough references that endpoint. Otherwise show "Ask Copilot to draft a walkthrough" as a substitute affordance.

A2.2
Cross-SDK content

SDK landing page contents.

The root inside an SDK (/[sdk]/) shows: working curl in the SDK's language, a capability hint strip, and direct links to each of the four groups for that SDK.

A4.2
Cross-SDK content

SDK-switching context preservation.

Switching the SDK picker mid-walkthrough or mid-endpoint preserves topic context. If equivalent page exists in target SDK, route there. If not, fall back to that SDK's Quick Start with a banner.

A4.3
Cross-SDK content

Walkthroughs author-once.

Walkthroughs live at /build/walkthroughs/... at portal root. Code samples per language. SDK picker filters which walkthroughs have samples in the active SDK.

A5.2
Cross-SDK content

Empty-group behaviour.

If a group node has no content for the active SDK, the header still shows. Empty state reads: "No Recipes for Python yet. Ask Copilot for a custom one, or browse Recipes in other SDKs."

A5.3
Access model

Operate public vs auth-gated.

Public: Status, Deprecations, Rate limits (general doc), Runbook. Auth-gated: Logs, Webhook events, Rate limits (your usage). Diego-Ops can verify the ops story before signup.

A4.4
Naming

Try It Out has two homes.

Inline on every endpoint page is primary. Standalone Reference › Try It Out is a fallback playground for users without a specific endpoint in mind. The duplication is deliberate.

A1.2
Naming

Changelog placement.

Changelog lives under Reference. URL: /reference/changelog. Linked from the deprecation calendar in Operate and from version-bump banners.

A1.1
Out of IA

Utility cluster and footer.

Top-right: Sign in, Pricing, Support. Outside the four cognitive groups but inside the portal chrome. Footer: Terms, Privacy, Cookies, Security disclosure, Status badge.

A6.2
Out of IA

Search results page format.

Results group by Quick Start, Build, Reference, Operate. Max 3 results per group above the fold. "More in [group]" link expands per group. Zero-result state offers Copilot prompt.

A6.3
Mobile + A11y

Accessibility scope statement.

Component-level a11y (focus traps, keyboard nav, contrast) is addressed in the wireframe spec at Deliverable 2, not at the IA level. The IA contributes by giving every navigable surface a clear semantic hierarchy and predictable keyboard reach.

A9.2
Mobile + A11y

Breadcrumb mobile truncation.

On viewports below 720px, truncate the middle of the breadcrumb: show first crumb + current crumb (e.g., NET ... › Get an album). Long-press reveals the full chain.

A9.3
Rules 05 / 09

Decisions made.

Three audit decision gates. All three resolved with Option A (the recommended path). Documented here so future revisits have a clear record of what was chosen and why.

GATE 1 · A4.1

Compliance placement

DecisionQuick Start › Compliance

Reza must see compliance evidence before any auth ask. Placing Compliance under Quick Start means it sits before authentication on the cognitive path. Under Operate would have required navigating past auth to reach it, breaking his evaluation flow.

GATE 2 · A5.1

Operate URL structure

Decision/operate/... at portal root

Operate content is cross-SDK by nature. Status, Deprecations, Rate limits, Runbook apply to the API itself, not to any specific SDK. Per-SDK duplication would create six surfaces × N SDKs = waste. Logs and Webhook events stay under the user's account scope.

GATE 3 · A6.1

API versioning surface

DecisionSDK × Version picker

The SDK picker becomes two-part: SDK on the left, API version on the right. Default: latest stable. The deprecation calendar in Operate deep-links into the version side of the picker. Versions as distinct SDKs would have lost semantic grouping.

Rules 06 / 09

Implementation phasing.

The Figma can show all surfaces. The engineering ship is staged. Three waves of decreasing build cost and increasing telemetry dependency.

Wave 1 · content-only

Ship the writing first.

Build effort: low · Content effort: medium
  • Recipes
  • Migrations
  • Runbook
  • Compliance
  • Changelog
  • Quick Start refinement (hero code, tier ladder)
  • Cross-link cross-references

No backend dependencies. The IA structure is purely informational at this stage. Reviewers see the portal's shape immediately. Maya, Aria, and Reza all unblocked in this wave.

Wave 2 · status + policy

Add operational visibility.

Build effort: medium · Pipeline dependency
  • Status (StatusPage or custom)
  • Deprecations (calendar + horizons)
  • Versioning policy publication
  • Subscribe affordance

Requires an uptime data pipeline and a published deprecation policy. Status surfaces become live. Diego-Ops's evaluation path unblocked. Reza's deprecation horizon visibility complete.

Wave 3 · per-key telemetry

Personal operations data.

Build effort: high · Storage + access infra
  • Logs (per-key request history)
  • Rate limits (live usage meter)
  • Webhook events (replay surface)

Requires per-developer telemetry storage and an access-controlled retrieval API. Sara's full operational reach. Liam's production debugging. The most expensive wave but the highest unique value once shipped.

Why 09 / 09

Why this label vocabulary.

Quick Start kept. Build, Reference, Operate added as new groups. Three reasons unchanged from v1. v2 adds two precision splits (SDKs / OpenAPI · Logs / Runbook) per audit A7.1 and A7.2.

01

Cost of renaming Quick Start is real.

Bookmarks, Stack Overflow answers, screenshots, internal team docs. Renaming would cost every existing reference. The audit confirmed the content was thin, not the label.

02

Three new groups deserve clean verbs.

Build, Reference, Operate. Industry-standard, action-led, scannable. v2 added Compliance under Quick Start (a noun) but the four group labels stayed verb-led for symmetry.

03

Four groups fit the rail.

Five would crowd a sidebar. Three would leave Operate as a footnote. Four is the right density for an SDK left rail. Confirmed by audit lens 7.

Naming precision splits applied in v2

Two compound nodes from v1 split into siblings per audit recommendations:

· SDKs & OpenAPI → Reference › SDKs + Reference › OpenAPI spec

· Logs & Runbook → Operate › Logs + Operate › Runbook
