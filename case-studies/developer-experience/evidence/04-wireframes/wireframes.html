Resonance Web API›Quick Start›Overview
Get started with the Resonance Web API
Make your first authenticated API call and start building in under 10 minutes. No prior Resonance API experience required.

Make your first call 1

curl Python JavaScript Java
# Get a track by Resonance ID curl -X GET "https://api.resonance.dev/v1/tracks/7qiZfU4dY1lWllzX7mPBI3" -H "Authorization: Bearer YOUR_ACCESS_TOKEN" # Response (200 OK) {"name": "Shape of You", "artists": [{"name": "Ed Sheeran"}], "album": {"name": "÷ (Divide)"}, "duration_ms": 233712, "popularity": 89, "preview_url": "https://p.scdn.co/..."}
🔒
Enterprise or regulated environment? Review our Compliance page - data residency, OAuth scope catalog, and rate limit policy - before proceeding with authentication. 2

Step-by-step setup 3

1
Create a Resonance Developer app
Go to the Resonance Developer Dashboard and create a new app. Note your Client ID and Client Secret - you'll need these to request access tokens.
2
Choose your authentication flow
Select the flow that matches your use case: Client Credentials for server-side app data, Authorization Code for user-specific data, or PKCE for mobile and single-page apps. See Authentication →
3
Request an access token
Exchange your credentials for a Bearer token. Tokens expire after 3600 seconds - your SDK handles refresh automatically.
curlPython
curl -X POST "https://accounts.resonance.com/api/token" -H "Content-Type: application/x-www-form-urlencoded" -d "grant_type=client_credentials&client_id=YOUR_ID&client_secret=YOUR_SECRET"
4
Make your first API call
Use the Bearer token in the Authorization header. The example at the top of this page uses a track ID from Resonance's catalog.

Resonance Web API›Quick Start›Authentication
Authentication
Choose the authentication flow that matches your use case. Start with the sandbox tier to explore the API without creating an account.
✓
Start without an account. The sandbox tier gives you read access to public Resonance catalog data - no credentials required. Upgrade when you need user data or write access.

Authentication tiers 1

1
Sandbox - No credentials required 2
No sign-up

Access public catalog data (tracks, albums, artists, search) using a shared read-only key. Rate-limited to 30 requests/minute. No user data.

curlPythonJavaScript
# Sandbox key - works immediately, no sign-up needed curl -X GET "https://api.resonance.dev/v1/tracks/7qiZfU4dY1lWllzX7mPBI3" -H "Authorization: Bearer BEACON_SANDBOX_KEY_2026" # Returns real Resonance catalog data

Limits: 30 req/min · Public data only · No user endpoints · No write access

2
Client Credentials - App-level access 3
App required

Server-to-server auth. Access public catalog data and app-owned resources. No user authorization required. Best for background services, batch processing, and catalog queries.

curlPython
# Step 1: Get access token curl -X POST "https://accounts.resonance.com/api/token" -d "grant_type=client_credentials&client_id=YOUR_ID&client_secret=YOUR_SECRET" # Step 2: Use token (expires in 3600s - SDK auto-refreshes) curl -H "Authorization: Bearer <token>" "https://api.resonance.dev/v1/search?q=radiohead&type=artist"
3
Authorization Code - User-level access
OAuth 2.0

Full OAuth 2.0 flow. Access user-specific data: listening history, playlists, player control. User must grant permission via Resonance's authorization page. Available in two variants:

Authorization Code
Server-side apps. Refresh tokens supported. Client secret stays on server.
PKCE (mobile / SPA)
No client secret needed. Code verifier replaces secret. Safe for public clients.
ℹ️
The scopes you request determine what data your app can access. See full scope catalog below ↓

All available scopes with the data they grant access to. Request only the scopes your app requires.

Resonance Web API›Quick Start›Compliance
Compliance & Trust 1
Data handling, security, rate limits, and API lifecycle policy for the Resonance Web API - reviewed this page before beginning authentication.
📋
This page summarises compliance-relevant information. For legal enquiries contact developer-legal@resonance.com. For full Terms of Service see developer.resonance.com/terms.

Data handling & residency 2

TopicDetail
Data residencyAPI infrastructure hosted in EU (Ireland) and US (Virginia). Region selection not available for Web API; data may transit both regions.
GDPR complianceResonance is a GDPR data controller for user data. Developers accessing user data via OAuth act as processors. See Data Processing Addendum for details.
Data retentionAccess tokens expire after 3600 seconds. Refresh tokens are long-lived and can be revoked via the Resonance Developer Dashboard at any time.
User data deletionDevelopers must honour deletion requests within 30 days. No Resonance user data may be stored beyond the session without explicit user consent.
Security transportAll API calls require HTTPS. TLS 1.2 minimum. No plain-HTTP support.
Audit loggingPer-key request logs available in Operate › Logs (authenticated access). Retention: 90 days.

Rate limits 3

Rate limits apply per access token, not per IP address. Upgrade your quota tier in the Resonance Developer Dashboard.

Sandbox30 req / minPublic catalog only · no user data
Development180 req / minFull API access · up to 25 users
