Resonance for Developers / Web API / Quick Start · Overview

Web API in 90 seconds.

A guided path from zero to first authenticated call. Pick an SDK, drop in your sandbox key, run the four steps below. Compliance, scopes, and migration paths are linked inline so nothing surprises you later.

~ 4 min read Web API · v2.43 Stable 7 languages
TL;DR · generated for this page grounded in v2.43 · 4 sources

The Web API is a REST surface that returns JSON. Authenticate with OAuth 2.0 (PKCE recommended for SPAs and mobile), or use Client Credentials for server-to-server reads of public catalog data. Rate limit is sliding-window per token, with headroom visible in X-RateLimit-Remaining. Start with GET /v1/tracks/{id} for a one-call dry run, then layer scopes as you add user-aware features.

Resonance for Developers / Quick Start / Authentication

Authentication, on a tier ladder.

Three rungs. Pick the lowest one that gives you what you need. Move up only when scope demands it. Each rung has working code, real scopes, and a clear answer to "what does this expose."

OAuth 2.0 · PKCE Sandbox first No-credit-card start
TL;DR · authentication in three sentences grounded in v2.43 · OAuth 2.0 spec

Start with the Anonymous rung for sample data, no setup. Promote to the Sandbox rung for live catalog reads without user context (server-to-server, Client Credentials grant). Use the OAuth rung with PKCE when you need user scopes (library, playlists, playback). All three return access tokens with the same Bearer envelope, so your call sites do not change between rungs.

The tier ladder is the central move on this screen F2.1

The live portal pushes users toward OAuth immediately, breaking Aria (code-shy) at the first step. The ladder lets evaluators try anonymously, then promote to Sandbox for catalog reads, then OAuth only when user scopes are actually needed. Same Bearer envelope across all three, so call sites never change.

GET /v1/tracks/{id} Stable since v1.0

Get track

Get Resonance catalog information for a single track identified by its unique Resonance ID. Returns a full Track object with album, artist, audio preview URL, and external IDs.

AI summary · grounded in v2.43 + 8 ref calls most common gotcha shown

Single-track lookup. The market param matters more than people expect: it controls relinking, available_markets, and is_playable. If the caller is a server (no user), pass an ISO country code or you will get nulls in playback fields. The endpoint is idempotent and cache-friendly; ETags are honored.

Scope none required
Rate class read · 1000 rpm
P50 38 ms
Cache private, max-age=60
Last changed v2.41 · Mar 2026
Gate A6.1 · SDK × Version picker in the header GATE

The current portal forces users to leave Reference to switch SDKs or API versions. The settled decision is a two-part persistent picker in the header. Switching SDK changes code samples in place. Switching version refreshes the response shape and parameter table. State persists across pages, so deep links land you where you were.

Path parameters 1 required

NameTypeInDescription
id* string path The Resonance ID of the track. Example: 3n3Ppam7vgaVa1iaRUc9Lp

Query parameters 1 optional · recommended

NameTypeInDescription
market string query An ISO 3166-1 alpha-2 country code. If specified, only content available in that market will be returned. If a valid user access token is supplied without market, the country associated with the user account is used. Recommended for server-to-server calls so is_playable resolves correctly.
